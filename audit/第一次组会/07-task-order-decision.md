# 任务顺序裁决：先做完 P1，再做 P2（2026-10-13）

> **裁决**：**在 P1 初稿完成之前，不并行推进 P2 的实验线**。P2 只保留零算力的维护性动作。
>
> **背景**：老师要求 **3 个月内交出 P1 初稿**。用户倾向"先把 P1 做完"，本文件给出**独立于该要求的
> 项目内在理由**，并把它固化为可执行的顺序，以免长对话里反复摇摆（见 `AGENTS-LESSONS.md` P6）。

---

## 1. 为什么"P1 单独做"优于"P1+P2 并行"

| # | 理由 | 依据（可核查） |
|---|---|---|
| **1** | **P1 是方法底座，其它四篇都建在它上面** | P4（IsoLNN 安全隔离层）明写"依赖 P1 控制器"；P2/P3/P5 的叙事都以 OTF 标量为前提。**P1 的结论决定另外四篇的卖点**——先做 P2 等于在未定地基上盖第二层 |
| **2** | **P1 已经走到"只差执行"，切换成本极高** | 环境自检 **10/10**、CfC 单元 **11/11**、指标 **8/8**、训练执行器已通过冒烟、A1 信息量版已出结论。此时抽身去做 P2，等于把已投入的基础设施闲置 |
| **3** | **P1 有一个"结论分叉点"即将到来** | 闭环 A1 是决定 P1 卖点的实验：若 OTF 有增益 → 主张"性能"；若无增益 → 主张"可解释性 + 零额外传感器成本"。**分叉未定前，写稿、排期、投哪个刊都定不下来**。而 P2 的新颖性依赖 OTF 作为"结构条件模态"的正当性——**P1 定调之前，P2 的定位也可能是错的方向** |
| **4** | **P2 有一个 P1 没有的重型依赖** | `AGENTS.md` §2 已记：**"OTF 自动标注流水线是 P2 的隐性关键路径，须在第 2 个月启动"**。这条流水线**尚未开工**，而它是 P2 训练数据的来源——并行做 P2 会立刻撞上它 |
| **5** | **注意力是最稀缺资源，而 deadline 是硬的** | 3 个月内一份初稿，需要连续的写作与实验窗口。P2 的现场只有"新颖性核验 + 文献图"（已完成），**没有任何实验资产**，现在开它等于从零起一条新线 |
| **6** | **负结果路径反而更需要专注** | 若闭环 A1 是负结果，P1 的写法要整体重构（卖点从性能改为可解释性），这时最不需要的就是另一条线的干扰 |

**反向考虑（我认真评估过，仍然支持单独做 P1）**：并行的唯一好处是"P2 早起步、抢时间窗"。
但 P2 的风险点是**被抢先**（见 `literature/p2/P2-novelty-check.md` 的 SPDiff/NIFTY 先例），
而抢时间的**有效手段是尽快把 P2 的新颖性钉死**——这件事**已经做完了**（双通道检索 + 正式版复核）。
所以"并行"能带来的边际收益很小，却要付出稀释 P1 专注度的代价。

## 2. 三个月路线（相对周，不写绝对日期；W1 = 用户确认后的第一个工作日）

| 阶段 | 内容 | 出口判据 |
|---|---|---|
| **W1** | ① 闭环 A1 中量验证（4 局）→ 通过后放全量（50 局，约 13 小时，可夜间跑）② **发出实车数据申请函**（见 §3） | 全量结果落盘、看护 G1/G2/G3 无异常 |
| **W2** | ① A1 配对统计与效应量（种子 ≥5、报 CI）② 决定 P1 叙事分支（正/负结果）③ 按分支重写摘要与 Fig.1（遵守 `AGENTS.md` §6.1 的 T-ITS/T-IV 写作纪律） | 一页 story 定稿：主张一句 + 证据等级 + 图表清单 |
| **W3–W4** | 补齐次要实验：PID/MPC 基线在同一协议下跑完；四类工况逐场景报告；长尾场景 | 主表数字齐全，可指到 `results/p1/*.json` |
| **W5–W6** | 写 Methods + Experiments（英文） | 两节完整、图表可独立读懂 |
| **W7–W8** | 写 Introduction + Related Work（引用库同源：`literature/library/P1-library.jsonl`） | 引用逐条核验、限定语逐字带上 |
| **W9** | 写 Abstract / Conclusion / Limitations（≥3 条具体限制） | 主张强度 ≤ 证据等级（铁律 2） |
| **W10** | 内部红队 + 图件定稿 + 补实验 | 三条致命质疑各有消解证据 |
| **W11–W12** | 全文打磨、cover letter、选刊确认（T-IV 首投 / T-ITS 备选，见 §6.1） | 提交前体检通过 |
| **缓冲** | W13 起留缓冲（负结果重构 / 补实验 / 数据到位后的实车回放） | — |

**并行允许的唯一 P2 动作（零算力）**：每轮收工顺手更新 `literature/p2/P2-novelty-check.md` 的
"新出现竞争工作"一节（若有）。**不允许**开 P2 的数据流水线或训练。

## 3. ★ 即时行动项：实车数据申请函（唯一的外部阻塞，必须本周发出）

**理由**：这是 P1 唯一**不在我们控制内**的前提（`AGENTS.md` §0.1：唯一实质缺口）。
申请函越早发出，对方回复与数据交付的时间越可能落在写作窗口内；
若拖到 W8 才发，数据到位时初稿已定，P1 就只能写"仿真 + 回放"。

**已经有了什么**：`audit/第一次组会/04-data-request-and-ethics.md` 含 8 条承诺
（含私有存储、`.gitignore` 排除、离线低粒度替代、撤回条款）。**该函至今未寄出。**

**建议**：本周内发出，并在 `04-` 文件里登记"已发出 + 日期 + 收件人 + 回复状态"。

## 4. 什么时候重新考虑 P2

满足**全部**下列条件后再启动 P2 实验线：

1. P1 初稿完成（或已投稿）；
2. 闭环 A1 的结论已定，且 P1 的叙事分支已冻结；
3. **OTF 自动标注流水线**已跑通并有质量报告（这是 P2 的关键路径）；
4. P2 的目标 venue 与条件模态消融实验设计已写死（防止看到结果再调口径）。
